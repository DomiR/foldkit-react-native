# Native performance measurements

These scripts measure the Android Expo showcase with Expo SDK 58, React Native 0.88, and Hermes. They use only the Android device selected by `--serial` or `emulator-5556` from the device driver. Port 8082 is the only Metro port used by this workflow.

## Bundle size

`bundleSize.ts` exports an HBC bundle and a source mapped JavaScript bundle, then reports raw and compressed sizes. It decodes flat and indexed source map version 3 mappings and assigns each generated byte range to a source file. Indexed sections are decoded with independent mapping state and their generated offsets bound each section's byte ranges. Unmapped bytes and newline bytes are reported as `[unmapped]`.

Source files are grouped by the last `node_modules` directory, by package manifests under the repository `packages` directory, or by the example directory. The report includes package totals and the largest files in `effect`, `foldkit`, and `@foldkit/native`.

Run it from the repository root:

```sh
node examples/native-showcase/scripts/perf/bundleSize.ts
```

Use `--out <dir>` to choose the output directory. Use `--skip-export` to reuse the existing `hbc` and `js` directories. The Markdown and JSON reports are written beside those directories.

## Startup measurement

`startup.ts` checks that the selected ADB device is ready, that Expo Go is installed, and that Metro reports `packager-status:running`. Each attempt force stops Expo Go, waits for the process to settle, clears logcat, opens the `exp://127.0.0.1:<port>` URL, and polls epoch logcat output for the startup payload. Warmup attempts are discarded. Three consecutive failed attempts stop the measurement.

The startup payload uses `performance.now()` values from the app. Intent to first commit uses the device epoch clock for both the Activity Manager start line and the performance log line. Summaries use nearest rank percentiles on sorted values.

`modulesEvaluatedToFirstView` measures from module evaluation to the first view because the first view renders synchronously inside `makeNativeProgram`. `programCreation` is makeNativeProgram including runtime start, init, and the first view.

```sh
node examples/native-showcase/scripts/perf/startup.ts --serial emulator-5556
node examples/native-showcase/scripts/perf/startup.ts --serial emulator-5556 --profile lowend --runs 10 --warmup 1 --timeout 90
```

The default JSON report is `.perf/startup-<profile>.json`, with a Markdown report beside it. Pass `--out <file>` to choose another JSON path.

Pass `--build-id <id>` to require the startup payload to carry that build ID. A launch with a different ID is recorded as a stale run, excluded from the summaries, and counted as a failed attempt. This catches Expo Go launching a cached bundle instead of the bundle served by the current Metro process. `measureDevice.sh` creates a build ID, clears Expo Go's package data once, gives the ID to Metro, and passes it to both measurement scripts.

## Render benchmark

`renderBench.ts` uses the same preflight and launch flow, then waits for `benchDone`. A `benchError` payload fails that attempt. Latency records are aggregated by phase across all successful launches. Burst records are grouped by message count and include throughput, update and view timing, commit ratios, and count delta mismatches.

```sh
node examples/native-showcase/scripts/perf/renderBench.ts --serial emulator-5556
node examples/native-showcase/scripts/perf/renderBench.ts --serial emulator-5556 --profile lowend --runs 3 --timeout 180
```

The default JSON report is `.perf/bench-<profile>.json`, with a Markdown report beside it. Pass `--out <file>` to choose another JSON path.

Pass `--build-id <id>` to require every benchmark payload to carry that build ID. A launch with a different ID is recorded as a stale run, excluded from the summaries, and counted as a failed attempt. Without this option, any payload build ID is accepted.

## Emulator and one shot measurement

`emulator.sh` owns a dedicated performance AVD named `Foldkit_Perf_API_35` by default. A second instance of an AVD that another emulator already runs without `-read-only` cannot boot, so the performance workflow copies only the source AVD `config.ini` and never reuses the source AVD state. The source AVD config is 1 core and 2048 MB. The `mid` profile uses 4 cores and 4096 MB. The `lowend` profile uses 2 cores and 2048 MB.

Create the dedicated AVD before the first measurement. The `start` command also creates it when needed. Expo Go SDK 58 is installed from `FOLDKIT_PERF_EXPO_GO_APK` or the newest matching APK in `$HOME/.expo/android-apk-cache`.

After boot and Expo Go installation, `start` requests the package dexopt job and waits for the first `/proc/loadavg` field to fall below 1.5, up to 300 seconds. It prints the load before and after this settle period.

```sh
examples/native-showcase/scripts/perf/emulator.sh create
examples/native-showcase/scripts/perf/emulator.sh start mid
examples/native-showcase/scripts/perf/emulator.sh status
examples/native-showcase/scripts/perf/emulator.sh stop
examples/native-showcase/scripts/perf/emulator.sh delete
```

Use `FOLDKIT_PERF_AVD` to choose another dedicated AVD name and `FOLDKIT_PERF_SOURCE_AVD` to choose another source AVD. Delete removes only the configured dedicated AVD and refuses when its name equals the source AVD name.

`measureDevice.sh` refuses to start when port 8082 is occupied. It starts the selected emulator, launches Metro in its own process group with performance logging enabled, waits for the packager status, runs startup and render measurements, then stops Metro and the emulator from an exit trap. A cleanup failure or measurement failure produces a nonzero exit status.

```sh
examples/native-showcase/scripts/perf/measureDevice.sh mid
examples/native-showcase/scripts/perf/measureDevice.sh lowend 10 3
```

Logs and reports are stored under `.perf`. The directory is ignored by the showcase Git configuration.
